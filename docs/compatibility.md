# Protocol compatibility ledger

The live preview targets Kitty 0.42.1 on Linux/Wayland. It has a real child
parser and PTY path; the table below describes its limited implementation.
This is not complete Kitty or xterm compatibility. Source pins are in
[sources.json](sources.json).

| Operation | Runtime behavior | Evidence / limits |
| --- | --- | --- |
| PTYs and lifecycle | Supported controlling terminals, resize, process groups, persistent daemon | Packaged runtime test; shell Ctrl-C, Ctrl-Z and fg; client death/reconnect |
| Text | Basic UTF-8 cells, rendition, cursor, margins, scrolling, erase/insert/delete, alternate screen | Mixed shell/graphics integration and SGR regressions; no scrollback, full grapheme handling, or complete xterm/terminfo claim |
| Graphics framing | Incremental APC with 16 KiB string limit; direct chunks up to 32 MiB total | Fragmented actual PTY producer; oversized controls discarded through termination |
| Encoding/compression | Base64, raw RGB/RGBA (`f=24/32`), optional `o=z` | Canonical base64 validation and exact bounded decoded length; 8192-pixel dimension and 32 MiB decoded-image limits |
| Native placement | `a=T`, plus basic transmit/put; pane-local image ID; one placement per image | Benchmark uses `p=1,C=1`; general multi-placement semantics are incomplete |
| Clipping | Native source crop generated by client inside pane rectangle, including cell offsets | Independent receiver checks oversized-image bounds; live two-app inspection |
| IDs/deletion | Client-local remapping; `d=a/A/i/I` scoped to originating pane | Two producers using image 7; deleting A preserves B; full lowercase retain-data semantics are incomplete |
| Queries/replies | Basic direct-image query and `q=0/1/2`; child replies generated by originating pane | Actual child query replies checked independently of focus; host replies never forwarded to a child |
| Repeated frames | Replace compressed asset; serialize outer upload; coalesce complete snapshots | Repeated actual browser updates plus synthetic PTY integration |
| Reconnect/layout | Text and current images reconstructed; two panes, zoom, swap and divider resize | Client SIGKILL, detached updates and fresh attachment tested; one interactive client |
| Keyboard/mouse/paste | Basic Kitty keyboard stack and legacy encoding; pixel/cell SGR mouse; focus and paste routing | Two-pane focus, coordinate translation and literal Ctrl-b inside paste tested; enhanced event/clipboard negotiation incomplete |
| PNG | Rejected | `f=100` unsupported |
| Local transfer | Partial | Ingress: complete raw RGB/RGBA POSIX shared memory, same UID and exact bounded length; no file/temp-file ingress, compression or subranges. Egress: capability-probed regular files, inline fallback. Immutable snapshots, delayed acknowledgements, client death and reconnect tested |
| Scaled/cropped child placements | Rejected | Child `c/r/x/y/w/h` unsupported; native outer clipping is supported |
| Unicode placeholders / relative placement | Rejected | `U/I/P/Q` unsupported; no virtual placement model |
| Animation / explicit layers | Rejected | Animation actions and `z` unsupported; repeated static frames work |
| General image scroll/erase/screen semantics | Incomplete / untested | Basic anchor scrolling and screen ownership exist; full G08/G09 suite remains open |

Unsupported or invalid graphics operations with a usable image ID receive an
error unless quiet mode suppresses it. Unknown control sequences are consumed,
not executed by the host. Malformed-input property coverage, all ID edges,
exhaustive cleanup and all GOAL.md release gates remain open.

The original M01 synthetic tests remain separate: rational clipping, checkerboard
source transforms, offsets, overlay subtraction, attachment IDs, short writes,
and decoded presentation reply ownership. They do not establish the unimplemented
runtime operations above. Original evidence remains in docs/evidence/m01.json.

## Actual applications

The browser pane runs zenbu-labs/terminal-browser at Ekko's pinned revision: `cce10b6131d15bf46a3e4b8dc827e0544ff7fc65`.
The Slack pane runs `~/dev/sandbox/terminal-slack`, revision
`03a8d78273159c7592b5555db36fc5f7da3b91f2`, with its pre-existing worktree state.
The launchers apply `patches/terminal-browser-session-transport.patch` to that
source in Nix, then reuse the terminal-slack browser build wrapper. Transport
preferences now come from the requesting session rather than the browser daemon.
Native Kitty RGBA frames negotiate shared memory; inline remains an explicit
override and fallback. No application UI or frame-rate policy is patched.

Launch argv is generated by scripts/benchmark.sh. Browser + Slack and shell +
browser use the same arbitrary-command PTY path. The earlier termweb/slack-term
candidates are superseded. Live acceptance established visible browser content
and Slack's workspace sign-in page; authenticated Slack usage remains untested.
